# 富文本編輯器重構完成報告

**日期**: 2026-02-07T16:00:00+08:00  
**類型**: 架構重構 - 消除程式碼重複  
**影響範圍**: ArticleEditor, CourseEditor, RichTextEditor (新), useRichTextEditor (新)

---

## 📋 專案概述

### 問題描述
使用者發現 CourseEditor 無法正常載入新的富文本編輯器功能,並指出 ArticleEditor 和 CourseEditor 之間存在大量重複的程式碼（約 1200 行工具列和編輯器配置）。

### 解決方案
依照 **DRY (Don't Repeat Yourself)** 和 **Single Responsibility Principle** 原則,將共用的編輯器邏輯提取到獨立的元件和 Hook 中。

```tsx
// 重構前 - 使用簡單 prompt
const handleInsertImage = useCallback(() => {
  const url = prompt("請輸入圖片網址 (建議使用 Cloudinary):");
  if (url && editor) {
    editor.chain().focus().setImage({ src: url }).run();
  }
}, [editor]);

// 重構後 - 使用美化對話框 + 驗證 + 即時預覽
const handleInsertImage = useCallback(async () => {
  const url = await dialog.prompt({
    title: "插入圖片",
    message: "請輸入 Cloudinary 圖片網址：",
    placeholder: "https://res.cloudinary.com/...",
    validation: (value) => {
      if (!isValidCloudinaryUrl(value)) {
        return "❌ 只能使用 Cloudinary 圖片網址！";
      }
      return null;
    },
    renderPreview: (value) => (
      isValidCloudinaryUrl(value) ? <img src={value} /> : null
    ),
  });
  // ... 插入邏輯
}, [editor, dialog]);
```

## 💡 經驗學習

### 成功因素
1. **使用者洞察**: 使用者準確識別出架構問題（「兩個理論上文字編輯器必須要用同個 component/utils」）
2. **漸進式重構**: 先建立共用元件,再逐一重構使用方
3. **保持相容性**: 保留所有現有功能,僅改變實作方式

### 設計原則應用
- ✅ **Single Responsibility**: RichTextEditor 只負責 UI, useRichTextEditor 只負責邏輯
- ✅ **DRY**: 消除 911 行重複程式碼
- ✅ **Open-Closed**: 新元件易於擴展,無需修改既有程式碼

### 可維護性提升
- **單一來源**: 工具列和編輯器配置現在只在一處維護
- **易於除錯**: 問題只需在 RichTextEditor 修復一次
- **一致性**: 確保 ArticleEditor 和 CourseEditor 行為完全一致
