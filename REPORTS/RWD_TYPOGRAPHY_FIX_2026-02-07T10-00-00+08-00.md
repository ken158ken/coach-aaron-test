## 問題描述

在 iPhone SE (375×667) 等手機裝置上：

1. **所有文字與間距過大** — `html { font-size: 20px }` 使所有 rem 值比標準大 25%
2. **AbyssScene 水母球佔滿整個手機螢幕** — radius=8 在 375px 寬螢幕佔 74% 寬度
3. **PrismScene 水晶在手機上無任何縮放** — 水晶佔螢幕寬度 58%
4. **Navbar 在平板上水平 padding 過多** — `md:px-16` 造成 768px 螢幕上浪費大量空間

---

## 根因分析

| 問題        | 根因                                  | 計算                                                          |
| ----------- | ------------------------------------- | ------------------------------------------------------------- |
| 文字膨脹    | `html { font-size: 20px }` 固定值     | `text-base` = 1rem = 20px（標準為 16px），膨脹 25%            |
| 球體過大    | SphereGeometry(8) + 0.8 scale         | FOV=75°, z=20, visible width≈17.3 units; 球體直徑 12.8 佔 74% |
| 水晶過大    | IcosahedronGeometry(2) 無手機縮放     | FOV=75°, z=8, visible width≈6.9 units; 水晶直徑 4 佔 58%      |
| Navbar 空間 | `md:px-16` = 4rem×2 = 160px@20px base | 768px 螢幕上 21% 是 padding                                   |

## 修復內容

### 1. `index.css` — 漸進式基礎字體 (clamp)

```css
/* 修改前 */
font-size: 20px;

/* 修改後 */
font-size: clamp(16px, 0.5vw + 14.5px, 20px);
```

**效果對照**:
| 裝置寬度 | 修改前 | 修改後 |
|----------|--------|--------|
| 375px (iPhone SE) | 20px | 16.4px |
| 640px (sm) | 20px | 17.7px |
| 768px (md) | 20px | 18.3px |
| 1024px (lg) | 20px | 19.6px |
| 1100px+ | 20px | 20px |

### 2. `AbyssScene.tsx` — 分級手機縮放 + 減少攝影機晃動

- `< 480px`: scale **0.45** (球體佔寬 33% → 合理)
- `480-768px`: scale **0.6** (球體佔寬 44%)
- `≥ 768px`: scale **1.0** (原始大小)
- 攝影機晃動: 手機 0.5 / 桌面 2

### 3. `PrismScene.tsx` — 新增手機端水晶縮放

- `< 480px`: scale **0.55** + 碎片半徑同步縮小
- `480-768px`: scale **0.7**
- `≥ 768px`: scale **1.0**
- 碎片分佈半徑按比例縮小
- 攝影機滑鼠跟隨幅度: 手機 2 / 桌面 5
- resize 時動態更新縮放

### 4. `Navbar.tsx` — 平板 padding 優化

```
修改前: px-4 sm:px-6 md:px-16 py-4 sm:py-6
修改後: px-4 sm:px-6 md:px-8 lg:px-16 py-3 sm:py-4 md:py-5
```

## 技術說明

### clamp() 計算原理

`clamp(16px, 0.5vw + 14.5px, 20px)`:

- **最小值**: 16px (保護極小螢幕)
- **偏好值**: 0.5vw + 14.5px (隨 viewport 線性增長)
- **最大值**: 20px (保留桌面端原始設計)

當 `0.5vw + 14.5px = 20px` 時，`vw = 11px`，即 `viewport = 1100px`。
因此 1100px 以上恆定為 20px。

### Three.js 視覺尺寸計算

FOV=75° 時，在相機距離 d 處可見寬度為：
$$W_{visible} = 2 \times d \times \tan(37.5°) \times \frac{W_{screen}}{H_{screen}}$$

AbyssScene (d=20, 375×667):
$$W = 2 \times 20 \times 0.767 \times 0.562 \approx 17.3 \text{ units}$$
