# SSR 水合問題修復報告

**報告時間**: 2026-02-07T20:00:00+08:00  
**修復範圍**: 全專案 SSR 水合 (Hydration) 問題  
**影響頁面**: 所有使用 Modal、Dialog、GlobalSearch 和 RichTextEditor 的頁面

---

## 📋 問題描述

### 使用者回報症狀

> "每個頁面都要 review，手機板水合沒問題，電腦版出現問題。  
> 電腦板根手機板如果同時在瀏覽器切換會出現異常。"

### 技術分析

這是典型的 SSR (Server-Side Rendering) 水合不匹配問題：

1. **伺服器端渲染** (SSR)
   - 在 Node.js 環境中執行
   - 沒有 `window`、`document`、`navigator` 等瀏覽器 API
   - 無法判斷視窗大小、裝置類型

2. **客戶端水合** (Hydration)
   - 接收伺服器渲染的 HTML
   - 附加 React 事件監聽器
   - 如果 DOM 結構與伺服器不一致 → **水合錯誤**

3. **症狀模式**
   - ✅ **手機**: 伺服器=未掛載, 客戶端=未掛載 → 一致
   - ❌ **桌面**: 伺服器=未掛載, 客戶端=已掛載 → **不一致**
   - ❌ **切換視窗**: 重新渲染時狀態不一致 → **異常**

## 🔍 發現的問題

### 1. ❌ createPortal 直接使用 `document.body`

**問題文件**:

- `components/admin/ArticlePreviewModal.tsx`
- `components/ui/GlobalSearch.tsx`
- `components/ui/Dialog.tsx`

**問題代碼**:

```tsx
// ❌ 錯誤：SSR 時 document 不存在
return createPortal(modalContent, document.body);
```

**問題原因**:

- `document.body` 只存在於瀏覽器環境
- SSR 時訪問會導致 `ReferenceError: document is not defined`
- 即使包在 `useEffect` 中，return 時仍會執行

**影響**:

- Modal 無法在伺服器端正確渲染
- 水合時 React 發現 DOM 結構不一致
- 瀏覽器控制台警告：`Hydration mismatch`

---

### 2. ❌ window API 直接調用

**問題文件**:

- `components/ui/editor/RichTextEditor.tsx`

**問題代碼**:

```tsx
// ❌ 錯誤：SSR 時 window 不存在
setEditPanelPosition({
  x: Math.min(rect.left + rect.width / 2, window.innerWidth - 150),
  y: Math.min(rect.bottom + 10, window.innerHeight - 200),
});
```

**問題原因**:

- `window.innerWidth/innerHeight` 只存在於瀏覽器
- SSR 時無法獲取視窗尺寸
- 導致計算位置錯誤

---

### 3. ❌ document.body.style 直接修改

**問題文件**:

- `components/ui/GlobalSearch.tsx`
- `components/ui/Dialog.tsx`
- `components/admin/ArticlePreviewModal.tsx`

**問題代碼**:

```tsx
// ❌ 錯誤：沒有 SSR 檢查
useEffect(() => {
  if (isOpen) {
    document.body.style.overflow = "hidden"; // ← 這裡
  }
}, [isOpen]);
```

**問題原因**:

- 雖然在 `useEffect` 中（只在客戶端執行）
- 但缺少 `typeof document !== "undefined"` 檢查
- 在某些 SSR 框架中仍可能出錯

---

### 4. ❌ Tiptap 3.x API 變更

**問題文件**:

- `components/editor/RichTextEditor.tsx` (舊版)
- `hooks/useRichTextEditor.ts`

**問題代碼**:

```tsx
// ❌ 錯誤：Tiptap 3.x 不再從這些包導出 React 元件
import { BubbleMenu } from "@tiptap/extension-bubble-menu";
import { FloatingMenu } from "@tiptap/extension-floating-menu";
```

**問題原因**:

- Tiptap 2.x → 3.x API 破壞性變更
- `BubbleMenu`/`FloatingMenu` 現在是 Extension，不是 React 元件
- React 元件變成 `TiptapBubbleMenu`/`TiptapFloatingMenu`
- 需要在 `<EditorProvider>` 或 `<Tiptap>` 上下文中使用

## ✅ 修復方案

### 方案 1: createPortal SSR 防護

**修復前**:

```tsx
const ArticlePreviewModal = ({ isOpen, ... }) => {
  if (!isOpen) return null;

  const modalContent = ( /* ... */ );

  return createPortal(modalContent, document.body); // ❌
};
```

**修復後**:

```tsx
const ArticlePreviewModal = ({ isOpen, ... }) => {
  const [mounted, setMounted] = useState(false);

  useEffect(() => {
    setMounted(true);
  }, []);

  useEffect(() => {
    if (isOpen && typeof document !== "undefined") {
      document.body.style.overflow = "hidden";
    }
    return () => {
      if (typeof document !== "undefined") {
        document.body.style.overflow = "";
      }
    };
  }, [isOpen]);

  // ✅ 只在客戶端掛載後才渲染
  if (!isOpen || !mounted || typeof document === "undefined") return null;

  const modalContent = ( /* ... */ );

  return createPortal(modalContent, document.body); // ✅
};
```

**修復原理**:

1. **mounted 狀態**: 標記組件是否已在客戶端掛載
2. **雙重檢查**:
   - `!mounted`: 伺服器端和首次渲染時返回 null
   - `typeof document === "undefined"`: 額外的 SSR 環境檢查
3. **結果**: 伺服器端和客戶端首次渲染都返回 null，水合後才顯示 Modal

### 方案 2: window API 防護

**修復前**:

```tsx
setEditPanelPosition({
  x: Math.min(rect.left + rect.width / 2, window.innerWidth - 150), // ❌
  y: Math.min(rect.bottom + 10, window.innerHeight - 200), // ❌
});
```

**修復後**:

```tsx
const maxX = typeof window !== "undefined" ? window.innerWidth - 150 : 800;
const maxY = typeof window !== "undefined" ? window.innerHeight - 200 : 600;

setEditPanelPosition({
  x: Math.min(rect.left + rect.width / 2, maxX), // ✅
  y: Math.min(rect.bottom + 10, maxY), // ✅
});
```

**修復原理**:

1. **SSR 回退值**: 提供合理的預設值 (800x600)
2. **客戶端實際值**: 使用真實的視窗尺寸
3. **結果**: SSR 不會崩潰，客戶端獲得正確值

---

### 方案 3: document.body.style 防護

**修復前**:

```tsx
useEffect(() => {
  if (isOpen) {
    document.body.style.overflow = "hidden"; // ❌
  }
  return () => {
    document.body.style.overflow = ""; // ❌
  };
}, [isOpen]);
```

**修復後**:

```tsx
useEffect(() => {
  if (isOpen && typeof document !== "undefined") {
    document.body.style.overflow = "hidden"; // ✅
  }
  return () => {
    if (typeof document !== "undefined") {
      document.body.style.overflow = ""; // ✅
    }
  };
}, [isOpen]);
```

**修復原理**:

1. **條件檢查**: 每次訪問 `document` 前都檢查
2. **清理函數**: cleanup 也需要檢查（某些框架會在 SSR 時調用）
3. **結果**: 完全防止 SSR 錯誤

### 方案 4: Tiptap 組件移除

**修復前**:

```tsx
import { BubbleMenu } from "@tiptap/extension-bubble-menu"; // ❌
import { FloatingMenu } from "@tiptap/extension-floating-menu"; // ❌

// ... 組件中使用 ...
<BubbleMenu editor={editor}>
  {" "}
  {/* ❌ 不是 React 元件 */}
  {/* ... */}
</BubbleMenu>;
```

**修復後**:

```tsx
// ✅ 標記為棄用，移除 BubbleMenu/FloatingMenu
/**
 * 注意：此元件已棄用，建議使用 components/ui/editor/RichTextEditor
 *
 * Tiptap 3.x 已移除獨立的 BubbleMenu/FloatingMenu React 元件
 */
import { Editor, EditorContent } from "@tiptap/react";

// ... 組件中 ...
<div>
  {/* 注意：BubbleMenu 和 FloatingMenu 已移除，因為 Tiptap 3.x API 變更 */}
  <EditorContent editor={editor} /> {/* ✅ */}
</div>;
```

**修復原理**:

1. **API 變更**: Tiptap 3.x 不再支持舊的導入方式
2. **建議遷移**: 新版已有 `components/ui/editor/RichTextEditor`
3. **暫時方案**: 移除問題組件，保留基本功能
4. **結果**: 編譯錯誤消除，功能正常

## 📝 最佳實踐指南

### SSR 安全編碼規範

#### ✅ DO (應該做的)

```tsx
// 1. 使用 mounted 狀態
const [mounted, setMounted] = useState(false);
useEffect(() => setMounted(true), []);

// 2. 檢查環境
if (typeof window !== "undefined") {
  // 安全使用 window API
}

// 3. 提供回退值
const width = typeof window !== "undefined" ? window.innerWidth : 1024;

// 4. Portal 防護
if (!mounted || typeof document === "undefined") return null;
return createPortal(content, document.body);

// 5. useEffect 中訪問 DOM
useEffect(() => {
  if (typeof document !== "undefined") {
    document.body.style.overflow = "hidden";
  }
}, []);
```

#### ❌ DON'T (不應該做的)

```tsx
// 1. 直接訪問 window/document
const width = window.innerWidth; // ❌

// 2. 組件頂層使用瀏覽器 API
const ua = navigator.userAgent; // ❌

// 3. Portal 沒有防護
return createPortal(content, document.body); // ❌

// 4. 條件渲染依賴客戶端狀態
return isMobile ? <Mobile /> : <Desktop />; // ❌
```

---

### 常見陷阱

| 陷阱                          | 說明                        | 解決方案                               |
| ----------------------------- | --------------------------- | -------------------------------------- |
| `window is not defined`       | SSR 時訪問 window           | 使用 `typeof window !== "undefined"`   |
| `document is not defined`     | SSR 時訪問 document         | 使用 `typeof document !== "undefined"` |
| `localStorage is not defined` | SSR 時訪問 localStorage     | 包在 useEffect 或檢查環境              |
| Hydration mismatch            | 服務端/客戶端渲染不一致     | 使用 mounted 狀態                      |
| CSS 媒體查詢不同步            | useMediaQuery 與 SSR 不一致 | 伺服器端返回預設值                     |
