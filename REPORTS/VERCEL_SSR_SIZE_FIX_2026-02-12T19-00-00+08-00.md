# Vercel SSR 函數大小超限修復報告

> **時間戳記**: 2026-02-12T19:00:00+08:00
> **修復者**: GitHub Copilot
> **狀態**: ✅ 修復完成

## 📋 問題描述

Vercel 部署失敗，錯誤訊息：

```
Error: The Vercel Function "api/ssr" is 636.02mb which exceeds the maximum size limit of 300mb.
```

## 🔍 根因分析

### 直接原因

`api/ssr.js` 的 Serverless Function 打包後大小為 636.02MB，超過 Vercel 的 300MB 限制。

### 深層原因

1. **@vercel/nft 依賴追蹤**：Vercel 使用 Node File Trace (NFT) 自動分析 `api/ssr.js` 的依賴圖
2. **ESM dynamic import 被追蹤**：原本使用 `import()` 載入 `entry-server.js`（ESM 格式），NFT 仍然嘗試追蹤其內部的模組依賴
3. **node_modules 被打包**：即使 `entry-server.js` 已是自包含 bundle（`noExternal: true`），NFT 仍將 `frontend/node_modules` 整個打包進函數
4. **excludeFiles 不足以對抗 NFT**：`vercel.json` 中的 `excludeFiles` 無法完全覆蓋 NFT 的靜態分析追蹤
5. **缺少 .nftignore**：沒有 `.nftignore` 檔案來明確告訴 NFT 應該忽略的路徑

### 大小組成估算

| 項目                                  | 大小        |
| ------------------------------------- | ----------- |
| `entry-server.js` (SSR bundle)        | ~5.5 MB     |
| `frontend/node_modules` (被 NFT 追蹤) | ~630 MB     |
| `index.html`                          | ~1 KB       |
| **總計**                              | **~636 MB** |

## 🛠️ 修復措施

### 1. SSR Bundle 格式改為 CJS (`frontend/vite.config.ts`)

```diff
  output: {
-   format: "esm",
-   entryFileNames: "[name].js",
+   format: "cjs",
+   entryFileNames: "[name].cjs",
    inlineDynamicImports: true,
  },
```

**原因**：CJS 格式讓 `api/ssr.js` 使用 `require()` 載入，而非 `import()`。`require()` 配合運行時拼接路徑可以完全阻斷 NFT 的靜態分析。

### 2. api/ssr.js 改用 require() 載入

- 將 `import()` 動態載入改為 `require()` 同步載入
- 使用 `path["resolve"](modulePath)` 運行時拼接路徑，阻斷 NFT 靜態分析
- 新增惰性載入模式（`loadServerModule()`），模組只載入一次

### 3. 建立 .nftignore

新增 `.nftignore` 檔案，明確排除：

- `frontend/node_modules/**`
- `frontend/src/**`
- `database/**`
- `REPORTS/**`
- `scripts/**`

### 4. 優化 vercel.json

```diff
  "api/ssr.js": {
    "maxDuration": 10,
-   "includeFiles": "{frontend/dist/server/entry-server.js,frontend/dist/client/index.html}",
-   "excludeFiles": "{frontend/node_modules/**,node_modules/**,backend/**,frontend/src/**}"
+   "includeFiles": "frontend/dist/{server/entry-server.cjs,client/index.html}"
  }
```

- 移除 `excludeFiles`（改用 `.nftignore` 更可靠）
- `includeFiles` 只包含必要的 2 個檔案

### 5. 更新本地開發伺服器 (`frontend/server.js`)

生產模式載入路徑從 `entry-server.js` 改為 `entry-server.cjs`。

### 6. 加強 .vercelignore

新增排除前端原始碼與配置檔案，減少部署檔案總量。

## 📊 預期效果

| 項目                  | 修復前                       | 修復後                                  |
| --------------------- | ---------------------------- | --------------------------------------- |
| NFT 追蹤範圍          | 整個 `frontend/node_modules` | 僅 `api/ssr.js` 本身的 Node.js 內建模組 |
| `includeFiles`        | 2 個檔案                     | 2 個檔案 (改為 .cjs)                    |
| SSR Function 預估大小 | 636.02 MB                    | ~6 MB                                   |
| 能否通過 300MB 限制   | ❌                           | ✅                                      |
