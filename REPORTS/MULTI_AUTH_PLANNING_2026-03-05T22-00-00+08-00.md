## 1. 現況分析

### 現有認證機制

| 項目         | 現況                                          |
| ------------ | --------------------------------------------- |
| 認證方式     | Email + 密碼（本地帳號）                      |
| 密碼加密     | bcryptjs（salt rounds: 10）                   |
| Session 機制 | JWT Cookie（httpOnly, secure, sameSite: lax） |
| Token 有效期 | 7 天                                          |
| 管理員驗證   | `admin_whitelist` 資料表比對                  |
| 速率限制     | 15 次 / 15 分鐘                               |

### 現有 Users 資料表欄位

```
user_id, auth_id, username, email, password_hash, phone_number,
display_name, avatar_url, sex, email_verified, is_active,
last_login_at, created_at, updated_at, deleted_at, avatar_base64
```

### 現有相關資料表

- `users` — 使用者主表
- `user_auth_tokens` — 目前為空，可用於 2FA 或 Token 管理
- `admin_whitelist` — 管理員白名單

## 3. Google OAuth 登入

### 3.1 流程圖

```
使用者                前端               後端 API            Google
  │                   │                   │                  │
  │ 點擊 Google 登入  │                   │                  │
  │──────────────────>│                   │                  │
  │                   │ GET /auth/google  │                  │
  │                   │──────────────────>│                  │
  │                   │                   │  重新導向到       │
  │                   │                   │  Google 授權頁面  │
  │<──────────────────────────────────────│─────────────────>│
  │                   │                   │                  │
  │ 使用者授權同意    │                   │                  │
  │──────────────────────────────────────────────────────>│
  │                   │                   │                  │
  │                   │                   │ Google 回調       │
  │                   │                   │ (含 auth code)    │
  │                   │                   │<─────────────────│
  │                   │                   │                  │
  │                   │                   │ 用 code 換取      │
  │                   │                   │ access_token      │
  │                   │                   │─────────────────>│
  │                   │                   │                  │
  │                   │                   │ 取得使用者資料    │
  │                   │                   │<─────────────────│
  │                   │                   │                  │
  │                   │                   │ 查詢/建立本地帳號 │
  │                   │                   │ 設定 JWT Cookie   │
  │                   │  重新導向到前端    │                  │
  │<──────────────────│<──────────────────│                  │
  │                   │                   │                  │
```

### 3.2 帳號綁定策略

| 情境                          | 處理方式                                          |
| ----------------------------- | ------------------------------------------------- |
| Google Email 與現有帳號相同   | 自動綁定，在 `user_social_accounts` 新增記錄      |
| Google Email 為新帳號         | 建立新 users 記錄 + social_accounts 記錄          |
| 已登入使用者點「綁定 Google」 | 僅新增 social_accounts 記錄，關聯現有 user        |
| 重複綁定                      | 檢查 provider + provider_user_id 唯一性，拒絕重複 |

### 3.3 所需套件

```json
{
  "passport": "^0.7.0",
  "passport-google-oauth20": "^2.0.0",
  "@types/passport": "^1.0.16",
  "@types/passport-google-oauth20": "^2.0.14"
}
```

### 3.4 Google Cloud Console 設定

1. 前往 [Google Cloud Console](https://console.cloud.google.com/)
2. 建立專案或選擇現有專案
3. 啟用 **Google+ API** 或 **People API**
4. 建立 OAuth 2.0 憑證（Web 應用程式）
5. 設定授權的重新導向 URI：
   - 開發: `http://localhost:5000/api/auth/google/callback`
   - 正式: `https://coach-aaron-test.vercel.app/api/auth/google/callback`
6. 取得 `GOOGLE_CLIENT_ID` 和 `GOOGLE_CLIENT_SECRET`

### 3.5 環境變數

```env
GOOGLE_CLIENT_ID=your_google_client_id
GOOGLE_CLIENT_SECRET=your_google_client_secret
GOOGLE_CALLBACK_URL=/api/auth/google/callback
```

5. 申請 Email 權限（需通過 LINE 審核）
6. 取得 `LINE_CHANNEL_ID` 和 `LINE_CHANNEL_SECRET`

| ---------- | ---------------------------------------------- |

| 使用者資料 | `https://api.line.me/v2/profile`               |
| 驗證 Token | `https://api.line.me/oauth2/v2.1/verify`       |

## 5. 2FA 雙因素認證（TOTP QR Code）

### 5.1 概述

- **類型**: TOTP（Time-based One-Time Password），相容 Google Authenticator / Authy / Microsoft Authenticator
- **強制性**: **不強制**，使用者可自行在設定頁面啟用/關閉
- **觸發時機**: 若使用者啟用 2FA，在完成 Email/密碼或社交登入後，需額外輸入 6 位數驗證碼

### 5.2 啟用 2FA 流程

```
使用者                前端               後端 API
  │                   │                   │
  │ 點擊「啟用 2FA」  │                   │
  │──────────────────>│                   │
  │                   │ POST /2fa/setup   │
  │                   │──────────────────>│
  │                   │                   │ 產生 TOTP Secret
  │                   │                   │ 產生 QR Code URL
  │                   │ 回傳 QR Code +    │
  │                   │ 備用碼            │
  │                   │<──────────────────│
  │                   │                   │
  │ 用 App 掃描 QR    │                   │
  │ 輸入 6 位驗證碼   │                   │
  │──────────────────>│                   │
  │                   │ POST /2fa/verify  │
  │                   │ (含驗證碼)         │
  │                   │──────────────────>│
  │                   │                   │ 驗證 TOTP 碼
  │                   │                   │ 啟用 2FA
  │                   │ 回傳成功           │
  │                   │<──────────────────│
  │                   │                   │
```

### 5.3 登入時 2FA 驗證流程

```
使用者                前端               後端 API
  │                   │                   │
  │ Email + 密碼登入  │                   │
  │──────────────────>│ POST /auth/login  │
  │                   │──────────────────>│
  │                   │                   │ 密碼驗證通過
  │                   │                   │ 檢查 2FA 啟用狀態
  │                   │                   │
  │                   │ 回傳 requires2FA  │
  │                   │ + tempToken       │
  │                   │<──────────────────│
  │                   │                   │
  │ 輸入 2FA 驗證碼   │                   │
  │──────────────────>│                   │
  │                   │ POST /2fa/login   │
  │                   │ (含 tempToken +   │
  │                   │  驗證碼)           │
  │                   │──────────────────>│
  │                   │                   │ 驗證 TOTP 碼
  │                   │                   │ 設定 JWT Cookie
  │                   │ 回傳登入成功       │
  │                   │<──────────────────│
```

### 5.4 備用碼機制

- 啟用 2FA 時產生 **10 組一次性備用碼**
- 每組為 8 位英數字混合
- 使用後立即作廢
- 用於手機遺失或 App 無法使用時的緊急登入
- 儲存在資料庫中（bcrypt 加密）

### 5.5 所需套件

```json
{
  "otplib": "^12.0.1",
  "qrcode": "^1.5.3",
  "@types/qrcode": "^1.5.5"
}
```

### 5.6 TOTP 參數設定

```typescript
{
  issuer: 'Coach Aaron',     // 在 Authenticator App 中顯示的名稱
  algorithm: 'SHA1',         // 雜湊演算法
  digits: 6,                 // 驗證碼位數
  period: 30,                // 更新週期（秒）
  window: 1                  // 容許的時間偏差（前後各 30 秒）
}
```

## 6. 資料庫變更規劃

### 6.1 新增資料表：`user_social_accounts`

```sql
-- 社交帳號綁定表
CREATE TABLE IF NOT EXISTS public.user_social_accounts (
  social_account_id SERIAL PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES public.users(user_id) ON DELETE CASCADE,
  provider VARCHAR(20) NOT NULL,                -- 'google', 'line'
  provider_user_id VARCHAR(255) NOT NULL,       -- 第三方平台的使用者 ID
  provider_email VARCHAR(255),                  -- 第三方平台的 Email
  provider_display_name VARCHAR(255),           -- 第三方平台的顯示名稱
  provider_avatar_url TEXT,                     -- 第三方平台的大頭照 URL
  access_token TEXT,                            -- OAuth access token（加密儲存）
  refresh_token TEXT,                           -- OAuth refresh token（加密儲存）
  token_expires_at TIMESTAMP,                   -- Token 過期時間
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(provider, provider_user_id),           -- 同平台同使用者 ID 唯一
  UNIQUE(user_id, provider)                     -- 一個使用者只能綁定一個同平台帳號
);

-- 索引
CREATE INDEX IF NOT EXISTS idx_social_accounts_user_id
  ON public.user_social_accounts(user_id);
CREATE INDEX IF NOT EXISTS idx_social_accounts_provider
  ON public.user_social_accounts(provider, provider_user_id);
```

### 6.2 修改 `users` 資料表

```sql
-- 新增認證相關欄位
ALTER TABLE public.users
  ADD COLUMN IF NOT EXISTS auth_provider VARCHAR(20) DEFAULT 'local',
  ADD COLUMN IF NOT EXISTS two_factor_enabled BOOLEAN DEFAULT FALSE,
  ADD COLUMN IF NOT EXISTS two_factor_secret TEXT,
  ADD COLUMN IF NOT EXISTS two_factor_backup_codes JSONB DEFAULT '[]';

-- auth_provider 可能的值: 'local', 'google', 'line', 'multiple'
-- two_factor_secret: 加密後的 TOTP 秘密金鑰
-- two_factor_backup_codes: JSON 陣列，存放 bcrypt 加密後的備用碼
```

### 6.3 利用現有 `user_auth_tokens` 資料表

```sql
-- 用於存放 2FA 登入的臨時 Token
-- user_auth_tokens 已存在，可直接使用
-- 欄位結構：
--   token_id, user_id, token_type, token_value,
--   expires_at, is_used, created_at

-- 使用情境：
--   token_type = '2fa_temp' → 2FA 驗證前的臨時 token
--   token_type = '2fa_backup' → 備用碼使用記錄
```

### 6.4 資料表關係圖

```
┌──────────────┐     1:N     ┌────────────────────────┐
│    users     │────────────>│  user_social_accounts  │
│              │             │                        │
│ user_id (PK) │             │ user_id (FK)           │
│ auth_provider│             │ provider               │
│ two_factor_* │             │ provider_user_id       │
│ ...          │             │ provider_email         │
│              │             │ access_token           │
└──────┬───────┘             └────────────────────────┘
       │
       │  1:N
       ▼
┌──────────────────┐
│ user_auth_tokens │
│                  │
│ user_id (FK)     │
│ token_type       │
│ token_value      │
```

## 9. 安全性考量

### 9.1 Token 安全

| 項目           | 措施                                        |
| -------------- | ------------------------------------------- |
| JWT Cookie     | httpOnly + Secure + SameSite: Lax（已實作） |
| 2FA Temp Token | 短效（5 分鐘過期），僅限單次使用            |
| OAuth Token    | 加密儲存（AES-256-GCM）                     |
| TOTP Secret    | 加密儲存（AES-256-GCM）                     |
| 備用碼         | bcrypt 加密，使用後立即標記作廢             |

### 9.2 防護措施

| 項目     | 措施                                          |
| -------- | --------------------------------------------- |
| CSRF     | SameSite Cookie + 社交登入使用 state 參數驗證 |
| 重放攻擊 | OAuth state 參數 + nonce 驗證                 |
| 暴力破解 | 速率限制（已有 authLimiter）                  |
| 帳號劫持 | 社交帳號綁定需驗證已登入身份                  |
| 2FA 繞過 | tempToken 嚴格驗證 + 短效期                   |

### 9.3 加密流程

```typescript
// TOTP Secret 加密儲存
import crypto from "crypto";

const ENCRYPTION_KEY = process.env.ENCRYPTION_KEY; // 32 bytes
const IV_LENGTH = 16;

function encrypt(text: string): string {
  const iv = crypto.randomBytes(IV_LENGTH);
  const cipher = crypto.createCipheriv("aes-256-gcm", ENCRYPTION_KEY, iv);
  let encrypted = cipher.update(text, "utf8", "hex");
  encrypted += cipher.final("hex");
  const authTag = cipher.getAuthTag().toString("hex");
  return iv.toString("hex") + ":" + authTag + ":" + encrypted;
}

function decrypt(text: string): string {
  const parts = text.split(":");
  const iv = Buffer.from(parts[0], "hex");
  const authTag = Buffer.from(parts[1], "hex");
  const encryptedText = parts[2];
  const decipher = crypto.createDecipheriv("aes-256-gcm", ENCRYPTION_KEY, iv);
  decipher.setAuthTag(authTag);
  let decrypted = decipher.update(encryptedText, "hex", "utf8");
  decrypted += decipher.final("utf8");
  return decrypted;
}
```
